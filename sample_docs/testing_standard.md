# 测试与缺陷处理规范（虚构示例）

## 用例设计

测试人员在需求评审后编写用例，覆盖主流程、边界值和异常路径。高优先级用例需要标明前置条件、操作步骤、预期结果和关联需求。接口测试应同时检查状态码、响应结构和关键业务字段。

跨浏览器功能上线前，至少在当前团队支持的浏览器版本中完成主流程验证。发现布局不一致时，应记录浏览器版本、分辨率、截图和复现步骤，便于前端定位。

## 缺陷处理

提交缺陷时应写明环境、复现步骤、实际结果、预期结果和附件。阻断性缺陷修复后，测试人员先回归原问题，再检查相关流程是否受到影响。无法复现的缺陷需要保留日志和发生时间供进一步排查。

缺陷关闭前，负责人必须确认修复版本和回归结果。延迟修复的低优先级问题需要记录风险接受人及后续处理计划。
