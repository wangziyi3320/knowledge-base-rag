# 项目协作手册

## 需求管理

项目需求需要先记录背景、目标用户、验收标准和优先级。需求评审通过后才能进入开发排期。范围发生变化时，应记录变更原因、影响模块和新的交付时间。

需求负责人需要把口头描述整理成可验证的用户故事，并说明正常流程、边界条件和异常流程。对于依赖外部接口的需求，还需要在评审阶段明确接口负责人、联调时间和模拟数据方案。没有验收标准的需求不能直接进入开发。

## 开发流程

开发人员从主分支创建功能分支。提交代码前需要完成本地测试，并在合并请求中说明改动范围、验证方法和潜在风险。至少一名成员完成代码审查后才可以合并。

代码提交应保持主题单一，避免把格式化、重构和功能改动混在同一次提交中。发现接口或数据结构变化时，开发人员需要同步更新接口文档，并提前通知受到影响的前端、后端和测试成员。

## 测试与发布

测试至少覆盖主流程、边界值和异常情况。阻断性缺陷必须在发布前关闭。发布完成后需要执行冒烟测试，并记录版本号、发布时间和回滚方案。

发布前由负责人检查配置文件、数据库变更、静态资源和依赖版本。冒烟测试应验证登录、核心业务流程和关键接口。如果发布后出现严重故障，应根据预先记录的回滚方案恢复稳定版本并保留故障日志。

## 文档与复盘

项目文档统一存放在团队知识库。每次迭代结束后进行复盘，记录有效做法、问题原因、后续行动和负责人。

复盘结论需要转化为可以跟踪的行动项，而不是只记录感受。每个行动项都应明确负责人、完成时间和验证方式，并在下一次迭代计划会议中检查执行情况。
